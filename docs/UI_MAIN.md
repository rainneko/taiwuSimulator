# 主界面模块设计（UI_MAIN）

> v0.1 · 2026-11-23 · 执行会话撰写
> 范围：主菜单、大地图界面、城镇界面、人物面板、门派 / NPC 交互界面，以及把它们串起来的场景切换与 DOM / three.js 分工。
> 不含：战斗界面（另有工单）、地区格子地图的细节（见 PLAN §4.2，本文只定它与其他界面的接口）、任何显示文案（全部走 `strings` 表，本文只用占位标签）。
> 依据：PLAN.md §2（分层）、§3（数据模型）、§4.0–4.3（渲染方案）。布局是本项目自己的设计，按「纸模剧场」的视觉语言组织，不以任何现成界面为蓝本。

## 1. 总体结构

### 1.1 画面分层

一个页面里只有一个 `<canvas>` 和一棵 Preact 树，自下而上六层：

| z | 层 | 技术 | 内容 | 是否吃指针事件 |
| --- | --- | --- | --- | --- |
| 0 | 场景层 | three.js（唯一的 `WebGLRenderer`） | 当前场景：菜单舞台 / 大地图 / 地区 / 城镇 | 是（DOM 没接住的才到这里） |
| 1 | 场景标注层 | DOM（`position: absolute`，每帧由场景投影坐标更新 `transform`） | 省名、建筑名牌、工人头顶气泡 | 否（`pointer-events: none`，个别可点的单独开） |
| 2 | HUD 层 | Preact | 顶栏（日期、行动力、资源）、底部快捷栏、小地图 | 是 |
| 3 | 面板层 | Preact | 人物面板、建筑详情、NPC 交互、门派面板。同一时刻最多 1 个主面板 + 1 个附属抽屉 | 是 |
| 4 | 模态层 | Preact | 确认框、设置、存读档、过月汇总 | 是（带遮罩，阻断下层） |
| 5 | 转场层 | three.js 全屏四边形（同一个 renderer 的最后一个 pass）+ DOM 加载提示 | 场景切换时的「纸幕」 | 是（切换期间吞掉所有输入） |

要点：

- **唯一 renderer、唯一 canvas**。场景切换不销毁 WebGL 上下文，只换 `Scene` 与 `Camera`；人物面板里的立绘小舞台用同一 renderer 的 scissor 视口画，不另开 canvas（WebGL 上下文数量有上限，且切换代价高）。
- **指针路由**：事件先到 DOM。HUD / 面板的根节点接住的就不再下传；落在空白处的由 `InputRouter` 转给当前场景的 `onPointer*`。拖拽地图时若指针划过面板，不中断拖拽（`setPointerCapture`）。
- **文字一律 DOM**。three.js 里不画可读文字（地图装饰性的大字除外），避免字体、换行、清晰度问题。

### 1.2 DOM 与 three.js 的分工原则

| 归 three.js | 归 DOM（Preact） |
| --- | --- |
| 有空间关系、要打光投影、要「立起来」的东西：地图纸片、建筑、棋子、舞台 | 一切文字、数字、列表、表单、按钮 |
| 与镜头运动绑定的反馈：悬停抬起、选中变色、翻起动画 | 与数据绑定的反馈：数值变化、进度条、提示、红点 |
| 转场 | 布局、滚动、键盘焦点、无障碍 |

判断标准一句话：**这个东西需要影子吗？** 需要就进场景，不需要就进 DOM。

### 1.3 状态流

```
core（纯逻辑状态）──每逻辑步后──▶ ui/store.ts（signals：只读快照 + 派生选择器）──▶ Preact 组件
        ▲                                   │
        └──────────── Command ◀─────────────┴──── 组件事件 / 场景拾取事件
```

- `ui/store.ts` 里分两类 signal：**游戏态镜像**（`time`、`player`、`town`、`world`…，由 `Game` 在每次逻辑步后整体替换引用，组件用 `computed` 取自己要的那一小块）和**纯界面态**（`screen`、`openPanel`、`selection`、`hover`、`modalStack`、`settings`）。
- 组件不直接改游戏态，只 `dispatch(Command)`；纯界面态可以直接改。
- 场景与 DOM 共享 `selection` / `hover` 两个 signal：在地图上点了某省，DOM 信息卡自动出现；在 DOM 列表里悬停某建筑，场景里对应立牌高亮。这是两层之间唯一的横向通道。

### 1.4 适配

- 设计基准 1920×1080；根字号 `clamp(12px, 0.833vw, 18px)`，面板尺寸全部用 `rem`。最小支持 1280×720。
- 宽高比：16:9 为主；更宽时两侧面板外扩、场景视野变宽；更窄（4:3、竖屏）时面板改为底部抽屉。竖屏与触控的完整适配在 M4 评估，本文各界面给出降级方式。
- 每个可点元素都能用键盘到达（`Tab` 顺序 = 视觉顺序），`Esc` 统一为「关最上层」。

## 2. 屏幕状态机

```
Boot ─资源清单与内容包校验─▶ MainMenu
MainMenu ─新建─▶ NewGame ─确认─▶ Town（出生村）
MainMenu ─继续 / 读档─▶ （存档里记录的屏幕：Town | Region | WorldMap）
Town ⇄ Region ⇄ WorldMap            # 三个「地点」屏幕，按层级上下钻
任一地点屏幕 ─遭遇 / 切磋─▶ Combat ─结束─▶ 返回原屏幕（战斗界面不在本文范围）
任一地点屏幕 + 面板：Character | NpcInteraction | Sect | BuildingDetail   # 面板不改变 screen
任一屏幕 + 模态：Settings | SaveLoad | Confirm | MonthSummary
```

```ts
// src/ui/store.ts
type Screen = 'boot' | 'mainMenu' | 'newGame' | 'worldMap' | 'region' | 'town' | 'combat';
type PanelId =
  | { kind: 'character'; charId: Id<'char'>; tab: 'attr' | 'arts' | 'equip' | 'septet' | 'relations' }
  | { kind: 'npc'; charId: Id<'char'>; view: 'talk' | 'askArt' | 'relations' | 'support' }
  | { kind: 'sect'; sectId: Id<'sect'>; tab: 'overview' | 'members' | 'arts' | 'support' }
  | { kind: 'building'; cell: number };

interface UiState {
  screen: Screen;
  transition: { from: Screen; to: Screen; progress: number } | null;
  panel: PanelId | null;          // 主面板，最多一个
  drawer: PanelId | null;         // 附属抽屉（如从 NPC 交互里再看对方人物面板）
  modalStack: ModalId[];
  selection: Selection | null;    // { type: 'province' | 'region' | 'cell' | 'char', id }
  hover: Selection | null;
}
```

规则：换 `screen` 必经转场（§3.2），换 `panel` 不经转场只做面板自身的进出动画；打开模态时逻辑时钟不走（本作非战斗部分本来就是回合制，仅影响场景里的待机动画是否降速）。

## 3. 场景切换技术方案

### 3.1 场景接口与管理器

```ts
// src/app/SceneManager.ts
interface IScene {
  readonly id: Screen;
  preload(assets: AssetCache): Promise<void>;   // 取图集、建几何；可被取消
  enter(params: unknown, from: Screen | null): void;   // 订阅 store、摆相机
  update(dt: number): void;                     // 弹簧、相机、标注层坐标
  render(r: THREE.WebGLRenderer, target: THREE.WebGLRenderTarget | null): void;
  onPointer(e: ScenePointerEvent): void;        // InputRouter 转来的指针事件
  exit(to: Screen): void;                       // 退订、停动画
  dispose(): void;                              // 释放 GPU 资源（由缓存策略决定何时调）
}

class SceneManager {
  private current: IScene | null;
  private cache: Map<Screen, IScene>;           // 已建好的场景
  async goto(to: Screen, params?: unknown, style?: TransitionStyle): Promise<void>;
}
```

`goto` 的时序：

```
1. ui.transition = {from, to, 0}；InputRouter 锁输入
2. 当前场景渲染到 rtA（定格一帧，之后不再 update）
3. 并行：播放「盖幕」前半段（0 → 0.5）  ‖  next.preload()
4. 前半段播完而 preload 未完 → 幕停在全盖状态，DOM 显示加载提示（纸条卷动的进度）
5. preload 完成 → current.exit()；next.enter(params, from)；next 渲染到 rtB
6. 播放后半段（0.5 → 1）：由 rtA 过渡到 rtB
7. ui.screen = to；ui.transition = null；解锁输入；按缓存策略决定是否 dispose 旧场景
```

盖幕前半段固定 ≥ 250ms，所以资源已在缓存时切换也不会一闪而过；`preload` 超过 8 秒给出重试按钮。

### 3.2 转场样式

转场是一个全屏 shader pass，输入 `rtA`、`rtB`、`progress` 和一张噪声 / 遮罩纹理。四种样式共用一套代码，只换遮罩与位移函数：

| 样式 | 用在 | 做法 |
| --- | --- | --- |
| `dive`（俯冲） | 大地图 → 地区，地区 → 城镇 | 前半段是**场景内**的相机推近（选中的那片纸放大到满屏），接一个 6 帧的交叉淡化；不盖幕，连续感最强 |
| `rise`（拉起） | 城镇 → 地区，地区 → 大地图 | `dive` 的逆过程：新场景从选中片的位置拉远 |
| `fold`（翻页） | 主菜单 ↔ 游戏内、过月 | 旧画面像一页纸沿竖轴折过去（顶点位移 + 背面用纸底色），露出新画面 |
| `tear`（撕幕） | 进出战斗 | 噪声遮罩从打击点向外撕开；参数由战斗模块传入，本模块只提供实现 |

`dive` / `rise` 需要两端场景对得上：切换前由当前场景给出「选中物在屏幕上的矩形」，下一个场景的初始相机据此反算，使第一帧的构图与上一帧末尾大致重合。对不上时退化为 `fold`。

### 3.3 资源与缓存

- `AssetCache`：按图集引用计数。三个地点场景共用 `paper-common` 图集（底纹、通用立牌、UI 用的纸纹）；各自的专属图集在 `preload` 里取。
- 场景实例缓存策略：`worldMap` 常驻（几何少、切换频繁）；`town` 与 `region` 保留最近使用的各 1 个，其余 `dispose`；`mainMenu` 进入游戏后立即释放。
- 预取：停在大地图且选中某省超过 0.5 秒，后台开始 `preload` 该省地区场景；在地区图上走到聚居点相邻格时预取城镇。
- 显存预算沿用 PLAN §4.0：贴图 ≤ 256MB，切换瞬间两场景并存时的峰值也要守住——所以 `rtA` 定格后旧场景可以先释放专属图集再等新场景加载。
- WebGL 上下文丢失：`renderer` 监听 `webglcontextlost / restored`，恢复后由 `SceneManager` 对当前场景重跑 `preload → enter`，UI 状态都在 store 里所以不丢。

### 3.4 面板里的小舞台（PortraitStage）

人物面板、NPC 交互面板需要一个「纸偶立绘」。它不是独立场景，而是当前场景渲染完成后追加的一次绘制：

```
renderer.setScissorTest(true)
renderer.setViewport(rect) ; renderer.setScissor(rect)   // rect 来自 DOM 占位元素的 getBoundingClientRect
renderer.render(portraitStage.scene, portraitStage.camera)
```

DOM 侧只放一个透明的占位 `<div ref>`，尺寸变化用 `ResizeObserver` 通知。面板滚动、动画期间每帧更新 rect。占位元素不可见（被别的面板盖住）时跳过绘制。

## 4. 各界面设计

约定：布局图里 `[ ]` 是 DOM 控件，`{ }` 是 three.js 场景里的东西，`( )` 是场景标注层。

### 4.1 主菜单

**布局**（16:9）

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                                                                              │
│   {纸模舞台：远山三层 → 中景村落立牌 → 近景树与草；整体缓慢左右视差}         │
│                                                                              │
│                                              ┌─────────────────────────┐     │
│         {标题牌：一张单独的大纸牌，          │ [继续]   ← 有存档才显示 │     │
│          进入时从地面翻起}                   │ [新的开始]              │     │
│                                              │ [读取存档]              │     │
│                                              │ [设置]                  │     │
│                                              │ [制作与素材声明]        │     │
│                                              └─────────────────────────┘     │
│  [版本号 · 内容包名]                                        [全屏] [静音]    │
└──────────────────────────────────────────────────────────────────────────────┘
```

**分工**

| three.js（`MenuScene`） | DOM |
| --- | --- |
| 4–5 层视差纸景；一盏缓慢移动的暖光（影子跟着走，一眼能看出是「立起来的纸」）；标题牌的铰链翻起；鼠标位置驱动 ±2° 的相机偏移 | 菜单按钮列、版本信息、设置 / 读档模态 |

**交互**

- 进入：舞台各层按远→近依次翻起（每层间隔 120ms），标题牌最后翻起，随后菜单列淡入。总时长 ≤ 1.6s，任意键跳过。
- 按钮悬停：DOM 按钮自身做纸片抬起（`transform` + 阴影）；同时把 `hover` 写进 store，舞台里对应的一盏小灯亮起（纯氛围，可关）。
- `新的开始` → `fold` 转场到 `NewGame`。
- `继续` → 读最近存档 → `fold` 到存档记录的屏幕。

**新建流程（NewGame）**——同一个 `MenuScene`，相机横移到舞台另一侧，DOM 换成三步向导：

```
步骤条：① 人物 → ② 出生地 → ③ 世界设定            [上一步] [下一步 / 开始]
① 左：{PortraitStage 纸偶，随选项实时换色换形}   右：[姓名] [性别] [外形滑条…] [资质点分配] [特性选择]
② 整屏：{简化版 WorldMapScene，只能选省}          右侧卡片：(省名)[该省简介][出生加成]
③ 表单：[难度各项下拉]（寿命、战斗难度、资源丰度…对应 PLAN §3.6 DifficultySettings）
```

第 ② 步直接复用 `WorldMapScene` 的 `pickOnly` 模式，这样「点哪片哪片变色」的地图在游戏开头就出现一次。

**降级**：竖屏时菜单列移到底部居中；`prefers-reduced-motion` 时去掉视差与翻起，直接显示。

### 4.2 大地图界面

**布局**

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [年·月] [行动力 ●●●○○] [银钱] [威望]                      [人物] [行囊] [☰]  │ ← 顶栏（各地点屏幕通用）
├──────────────────────────────────────────────────────────────────────────────┤
│                                                             ┌──────────────┐ │
│      {纸雕地图：15 片省域分 3–4 档高度叠放；                │ (省名)       │ │
│       上层：山脉立牌、河流纸条、云}                         │ [势力·立场]  │ │
│                                                             │ [恩义  ▓▓░░] │ │
│            (省名标注，随缩放淡入淡出)                       │ ──────────── │ │
│                                                             │ 地区：       │ │
│      {当前所在省：一枚棋子立牌}                             │ [省会  10AP] │ │
│                                                             │ [门派  10AP] │ │
│                                                             │ [乡村  未通] │ │
│                                                             │ [前往]       │ │
│  [图层：势力 / 恩义 / 驿路]                                 └──────────────┘ │
│  [− 缩放 +] [回到所在地]                                     ↑ 选中省后滑出  │
└──────────────────────────────────────────────────────────────────────────────┘
```

**分工**

| three.js（`WorldMapScene`） | DOM |
| --- | --- |
| 省域纸片（`ProvincePiece`：挤出几何 + 纸材质）、叠层高度、悬停抬起、选中变色、其余压暗；装饰层视差；棋子；驿路（已打通的省之间一条虚线纸带）；相机拖拽缩放 | 顶栏、右侧省信息卡、图层切换、缩放控件、省名标注（标注层） |

**交互与状态**

| 省域状态 | 触发 | 目标外观（弹簧追踪，≈ 180ms） |
| --- | --- | --- |
| `idle` | — | 基础高度、底色（低饱和） |
| `hover` | 指针在其上 | 高度 +0.04，边缘白边加亮，光标变手型 |
| `selected` | 点击 | 高度升到最高档 +0.08，颜色过渡到该省主题色（OKLab 插值），投影加深 |
| `dimmed` | 有其他省被选中 | 亮度 ×0.8，饱和度 ×0.6 |
| `locked` | 不可进入 / 未打通且不相邻 | 灰纸、不响应悬停，点击只弹出原因提示 |

- 单击选中 → 右侧信息卡滑出，列出该省 3 个地区及各自所需行动力（`ProvinceDef.travelCost`、是否已打通驿路）；再点地区行或 `[前往]` → 确认（扣行动力）→ `dive` 转场进 `Region`。
- 图层切换改的是「未选中时各省的底色」：势力图层按势力主色，恩义图层按恩义值做同色相深浅，驿路图层突出已打通的连线。选中变色的规则不受图层影响。
- 拖拽平移、滚轮 / 双指缩放；缩放到一定程度省名标注淡出、山脉立牌淡入，避免拥挤。
- 键盘：方向键在相邻省之间移动选择（预先算好邻接表），`Enter` 等于 `[前往]`。

**拾取**：省片数 < 40，直接 `Raycaster` 对省片网格求交；装饰层设 `layers` 掩码不参与拾取。

**数据来源**：`world.provinces`、`RegionState.unlocked / goodwill`、`player.location`、`time.ap`。命令：`TravelTo { regionId }`。

**降级**：窄屏时信息卡改为底部抽屉；触屏没有悬停，第一次点 = 选中，第二次点同一片 = 打开信息卡。

| 地基与 169 个格子；建筑纸模（`BuildingKit`，走 `PaperBatch` 合批）；资源点地块；工人牌；建造 / 升级 / 拆除的铰链动画；格子悬停与选中高亮；可建范围提示（绿色 / 灰色底纸）；季节色板 | 顶栏、左侧资源与人力、施工队列、右侧详情 / 建造列表、底部工具条、建筑头顶状态气泡（标注层）、过月汇总模态 |

**交互**

- **格子拾取**：射线与地面平面求交 → 逆变换到网格坐标 → 取整；不对建筑网格做 raycast（合批后也不好做）。建筑比格子高，点到立牌上半部分时按「屏幕空间向下投到地面」修正：先用立牌包围盒做一次粗判，命中则取该建筑所在格。
- **悬停**：格子底纸提亮；右侧详情不变（避免闪烁），只在标注层显示一行名称。
- **选中**：格子抬起 0.03，建筑轻微前倾再回正（铰链 ±4°）；右侧详情换成该格内容。空地 → 可建造列表（按类别分组，灰显并标明缺什么：图纸、资源、人力、邻接条件）。
- **建造模式**（点 `[建造]` 或在列表里选了建筑）：场景进入放置态，所有合法空地铺绿色底纸（合法 = 距已有建筑正交 2 格或斜向 1 格以内，且满足邻接资源点要求），非法格压暗；指针所在格显示半透明的建筑预览牌；左键确认、右键 / `Esc` 取消。确认后 `dispatch(Build { cell, defId, manpower })`，该格立起脚手架（建筑牌以 15° 半立）。
- **派工**：把左下 `[村民]` 列表里的人拖到建筑上，或在详情里点 `[经营者 ＋]` 从列表选。拖拽时 DOM 的拖影跟手，场景里可放置的建筑高亮；松手位置由 `InputRouter` 交给场景做格子拾取。
- **过月**：`[过月 ▶]` → 确认 → `fold` 转场（旧画面折过去）→ 逻辑层跑过月管线 → 新画面展开时，本月完工的建筑依次翻起、产出气泡依次冒出 → 弹出过月汇总模态（DOM 列表，可逐条点击定位到对应格）。
- **视角**：固定视角，俯角 53°、朝向不变，不可环绕——像翻开的立体书，所有纸模只需要正面好看。只保留拖拽平移（限制在地基范围内，边缘留 1 格余量）和滚轮 3 档缩放。固定视角下后排建筑会被前排遮挡：选中格所在行之前的建筑立牌自动压低透明度到 35%（材质 uniform，逐实例），鼠标移开后恢复。
- **进入建筑**：`[进入]` 打开该建筑的功能面板（工坊制造、练功房修习、藏书处研读…各是一个 DOM 面板，不换场景）。

**数据来源**：`TownState.cells / manpower / stock / jobs`、`BuildingDef`、`time`。命令：`Build`、`Upgrade`、`Demolish`、`AssignWorker`、`Gather`、`EndMonth`。

**标注层的数量控制**：169 格最多同时显示 30 个气泡（按离屏幕中心的距离排序），其余合并为格子上的一个小色点，避免 DOM 节点过多。

**降级**：窄屏时左栏折叠成顶栏下的一行资源图标，右栏改底部抽屉；触屏用单指拖拽平移、双指捏合缩放。

## 6. 实施顺序与验收

| 序 | 内容 | 依赖 | 估时 |
| --- | --- | --- | --- |
| 1 | 分层骨架：`InputRouter`、`ui/store`、`SceneManager` + `TransitionPass(fold)`、顶栏、`ModalHost` | PLAN M1 的工程骨架 | 3 天 |
| 2 | `MenuScene` + 主菜单 + 设置 / 存读档模态 | 1 | 2 天 |
| 3 | `WorldMapScene`（省片五态、拾取、信息卡、`dive / rise`） | 1，省轮廓数据 | 4 天 |
| 4 | `TownScene`（网格、`BuildingKit`、建造模式、派工、过月演出） | 1，`core/town` | 6 天 |
| 5 | `PortraitStage` + 人物面板五个页签 | `core/character`、`core/martial` | 5 天 |
| 6 | NPC 交互面板 + 门派面板 | 5，`core/character/relations` | 5 天 |
| 7 | 新建流程向导 | 2、3、5 | 2 天 |

第 1–4 步对应 PLAN 的 M3，5 对应 M2 末尾（人物系统做完即可接），6 对应 M4。

**验收**

- 任意两个地点屏幕间切换：已缓存时 ≤ 700ms，首次加载时幕不闪、有进度提示。
- 大地图：悬停到抬起 ≤ 1 帧延迟；连续快速划过多片时无残留高亮。
- 城镇：满铺 169 格时 60fps（集显 1080p）；建造模式下可建范围显示与逻辑层判定逐格一致（自动化测试对拍）。
- 人物面板开关不引起场景掉帧；`PortraitStage` 的 rect 在面板滚动 / 缩放时始终对齐（截图比对）。
- 全程可只用键盘完成「新建 → 进村 → 建一栋建筑 → 过月 → 去另一个省」。
- 互动列表、可建造列表里每个灰显项都能说出具体原因。
