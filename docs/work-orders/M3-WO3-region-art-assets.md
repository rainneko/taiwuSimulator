### 1.2 物理尺寸的取值理由

镜头俯角 53°、朝向固定。一张立正的牌在屏幕上的竖向长度是物理高 × cos 53° ≈ **0.60**，地面的纵深是 × sin 53° ≈ **0.80**。所以「高 1.5 的城」在屏幕上约占 0.9 个格宽的高度、压住身后约 1.1 行格子——这正是立体书「近处的东西挡住远处」的层次，不需要再缩。

- **城 1.3 × 1.15、门派驻地 1.3 × 1.2**（v1.1）：宽度超出本格 0.15，向左右邻格各伸出一点——聚居点是地区里的地标，比一格里的其他东西大一号；近档下一座城差不多占满中间那一格。门派驻地高出一点是因为它的原型多是层层升高的殿阁（§5 的原型清单），竖向信息更多。
- **小镇、寨子 1.05 × 0.9；村庄 1.0 × 0.75**（v1.1）：保持「城 > 镇 = 寨 > 村 > 地形立牌」的层级，村庄比最高的树（0.65）高一点，在林子里也认得出。
- **野外地点与标记 0.65 × 0.65**（v1.1）：与最高的地形立牌同高，靠造型而不是体量区分。奇遇标记另有运行时的浮动与微光（§3.7），不靠尺寸抢眼。
- **地形立牌 0.45–0.65（一格的主体层，v1.1）**：用户给的「九格」示意里一格是一个小场景，树约半格高、一格四五棵；逐项按物体本来的比例定（草丛 0.45、树 0.62、山峰 0.5——v1.3.1 由 0.65 缩小），见 §1.3。一格放几张见 §1.4——林地 4–6 棵、密林 5–7 棵，「森林探险感」主要靠它。
- **图按正常比例画，压缩由物理高度补偿**：立起来的牌在 53° 俯角下竖向只剩 0.6，这正是纸模「立起来的牌」该有的样子；需要它在屏幕上显得更高时，调清单里的物理高度，**不让图里的物体竖向拉长**。prompt 里明写「按物体本来的比例画，不要竖向拉长，也不要压扁」（§2.2）。
- **前景小件 0.2–0.33**：放在地点主牌前面（§3.7），矮于主牌高度的三分之一，才能露出主牌的下半部。

**屏幕密度与缩放三档（v1.1，用户 2026-11-23 定）**：格子放大到原方案的 4 倍面积。`FollowRig` 三档（1080p）：

| 档 | 横向格数 | px / 格 | 看到什么 |
| --- | --- | --- | --- |
| 近（默认进入地区时） | 3 | 约 640 | 棋子所在格与周围 3×3 九格占满画面（按用户给的示意：中间一行完整，远、近两行各露出一部分），九格之外是灰的（§3.4 的「视野外」） |
| 中 | 6 | 320 | 视野与周边地形 |
| 远 | 整张地区装进画面（15×15 时约 23 格横宽） | 约 85 | 缩略图：看全区地形、聚居点与道路 |

格子变大后地区的格数建议降到原来的 1/4（§4），远档整张地区仍能装进一屏。

入库像素密度（v1.1）：地形立牌、填充小件、地面散件、前景件 **768px / 格**，地点 **640px / 格**，专属地点 **768px / 格**，底纸跟画质档走（v1.2）：**high 1024²（512 texel / 格）、medium / low 768²（384 texel / 格）**，一张覆盖 2×2 格；出图本来就是 1024²，不用重出。依据：近档 640px / 格时，0.6 高、0.5 宽的树在屏幕上约 320px 宽，图集里 384px（DPR 1 约 1.2 倍，DPR 2 约 0.6 倍），竖向因 0.6 的压缩再多约 1.7 倍；城 1.3 宽在屏幕上约 830px，图集里 832px。来源图 1024² 里一棵树约 900px 高，缩到 0.62 × 768 ≈ 476px，不放大。**近档底纸的清晰度（v1.2 执行主管裁定）**：近档 640px / 格时，medium 的 384 texel 约 0.6 倍、high 的 512 texel 约 0.8 倍。不加锐化滤镜（多 4 次采样，还会把纸纤维和淡墨晕染锐化出噪点），改为三件事：① 入库分辨率跟画质档走（上面）；② 近档把 `PaperMaterial` 的世界空间纸纤维当细节层——地面的 `uPaperFibre` 随缩放从远档 0.22 过渡到近档约 0.35，放大后的底纸靠真实分辨率的纸纹保持「是一张纸」的锐度；③ 近档的清晰细节由平贴的地面散件（图集里 768px / 格）和填充小件负责，底纸只提供大块色面与纹理。最终取 768² 还是 1024² 作为缺省，试点时用 `preview_grid.py --ground-px` 对比后定（§7）。

`pack_atlas.py --dry-run` 实测：地形图集 40 帧占 4096×2048 的 76%，地点图集 16 帧占 71%，细节图集（填充小件 + 地面散件）27 帧占 2048×1024 的 67%，专属地点 2 帧占 2048² 的 44%。地形图集余量不多（还能加 6–8 帧）；要再加帧就拆成第二页。

### 1.4 一格的三层（v1.1）

参考 papertrails 的做法与用户给的「九格」示意后（papertrails 一块地有 10–30 张卡：几棵树 + 一圈灌木、草、花、石头、蘑菇 + 印在页面上的小路与色斑；示意里中间一格是小路、路牌、灯柱、几丛花灌木和石头），本工单把一格从「一两张立牌」改为**一个小场景**，分三层：

| 层 | 内容 | 每格张数 | 素材 |
| --- | --- | --- | --- |
| 主体 | 地形立牌（树、山峰、石柱…），高 0.45–0.65 | 0–7，按地形（§1.3） | B，每种地形 2 张 |
| 填充 | 低矮的共用小件（灌木、草簇、野花、石块、蘑菇、树桩…），高 0.1–0.3 | 0–8，按地形的池（§1.5） | H，17 张，各地形共用、运行时按地形 / 季节染色 |
| 地面 | 平贴在地上的薄纸件（落叶、苔藓、碎石、水洼、花瓣…），不立起 | 0–3，按地形的池（§1.5） | I，10 张，随机转角 |

- 主体上限 7（槽位数），张数多时整体略缩（4 张 ×0.95、5 张 ×0.92、6 张 ×0.88、7 张 ×0.85），免得一格挤成一堵墙。
- **地点格**：主牌 + 至多 2 张前景件 + 地面散件；野外地点格 1 张主牌。聚居格、野外地点格不放地形立牌与填充小件。
- 开阔地形（湖泊、农田）主体 0–1 张、原野 0–2 张，留出空地；林地 4–6 张、密林 5–7 张，读出「密」——对照用户给的示意，林子那一格是四五棵树加一圈灌木与花。
- 为什么用共用填充件而不是给每种地形各画一套：17 张共用件 × 地形染色就能让每格都有细节且各不相同，素材量只多 27 张；每种地形各画 3–4 张填充件要多 60 张以上，风格也更难统一。

## 2. 出图规范

prompt 全部由 `tools/art/region_prompts.py` 从数据表展开，**改需求改表，不手改 `region.md`**。每条 prompt = 公共风格段 + 光照段 + 内容 + 该类的公共约束。

### 2.1 公共风格段（v1.3：模切卡纸 + 正面印手绘插画；底纸另用平面印刷纸面）

v1.0–v1.1 的风格段写的是「多层厚卡纸裁切叠贴、每层都有接触阴影」，按参考截图核对后改成参考截图的真实做法：**每个物体是一张模切下来的厚卡纸片，正面印着一幅手绘插画**，叠层只在树冠、屋顶、山石处出现两三层。试点 6 张证明这样写出来的立牌最接近参考（§7.4）。生成器里的常量是 `STYLE`（立牌、地点、填充、散件、装饰）与 `GROUND_STYLE`（底纸）。

| 句子（`STYLE`） | 为什么 |
| --- | --- |
| 每个物体是一张从厚卡纸上模切下来的纸片，正面印着手绘插画：水粉、水彩笔触，装饰性图案细节（叶片纹样、瓦片、木纹、石面皴擦），干净的深色细线勾轮廓，纸面有宣纸纤维 | 参考截图的质感来自「插画印在纸片上」，而不是「纸片本身很多层」；纸片的厚度与白边由运行时的 `PaperMaterial` 给（WO1 §2.1），图里只画正面 |
| 树冠、屋顶、山石可以由两三张纸片前后叠贴，层间一道细窄的接触阴影，切口露一线白色纸芯 | 把叠层限定在最能体现立体书的部位；处处叠层会让画面碎、64px 下读不出剪影 |
| 造型概括、可爱而不幼稚，剪影干净利落 | 中档立牌只有 60–120px 高，靠剪影识别 |
| 配色温和、略低饱和：宣纸米白、赭石、土黄、苔绿、靛青与墨色为主 | 低饱和才能在运行时被季节染色、压暗、选中变色而不脏 |
| 只在局部用少量淡墨晕染、点苔或枯笔皴擦，约占画面两成，不要大面积水墨渲染 | 「水墨两成」的落点；把水墨限定成点缀，避免模型滑向整幅水墨画 |
| 淡墨不要形成任何像文字、符号、印章的笔画 | 墨笔触是模型画出「伪书法」「伪印章」的主要入口，单独封住 |
| 没有任何文字、字母、数字、印章、签名、水印、边框，也没有人物和动物 | 名称由界面显示；人物是另一套素材；动物会干扰同类立牌的辨识 |
| 风格段只写质感，不写任何具体作品或游戏的名字 | 参考截图由出图方另附（§7 第 0 步），文字里点名会把模型引向仿制 |

| 句子（`GROUND_STYLE`，v1.3 新增） | 为什么 |
| --- | --- |
| 整幅是一张平铺的厚卡纸，纸面上印着手绘插画（草叶、落叶、苔点、石纹的纹样） | 试点里底纸沿用 `STYLE` 时，「每个物体是一张模切纸片」让模型把草簇、树冠画成站立件，平铺后像一地小立牌 |
| 所有元素都是印在纸上的平面纹样：没有立起来的纸片、没有叠贴的纸层、没有纸芯白边、没有任何阴影或暗沿 | 「接触阴影四周均匀、很浅」在底纸里仍会被画成明显的暗沿，旋转平铺后成规律的暗格；底纸干脆不要阴影 |
| 画面安静、元素细碎，比立在上面的树木、房屋立牌简单得多 | 立牌与底纸要分开层次；参考截图的地面明显比立件安静 |

光照段：立牌、边框件用「**光从左上方来**，接触阴影落在每层的右下侧」，与场景主光（WO1 `warmDay` 的 key 光在 `(-5, 8, 3)`）一致；道路、地面散件用「**均匀漫射光**，接触阴影四周均匀、很浅」，因为运行时会旋转、镜像使用（§3.2）；底纸不加光照段（`GROUND_STYLE` 已写「没有任何阴影」）；单栋房屋（J 类）与其他立牌相同。

### 2.2 立牌的公共约束

| 约束 | 为什么 |
| --- | --- |
| 一个物体或一组紧挨着的物体，作为一整块剪影；四周留约 8% 空白 | 留白给抠像与裁边容错；「一整块」保证 alpha 镂空后是一张牌而不是几张碎片 |
| 按物体本来的比例画，不要竖向拉长，也不要压扁 | 立起来的牌在屏幕上竖向只剩 0.6，这由物理高度补偿（§1.2）；模型若自作主张「预先拉长」来抵消，同类牌的比例就会忽高忽低，在界面里平视展示时也会变形 |
| 正面平视、略带俯角约 15°，不要强透视、不要高空俯拍 | 牌是立在地上的平面，场景的 53° 俯角已经提供了俯视感；图里再画强俯视会「双重俯视」，屋顶像要翻过来 |
| 主体最下缘是一条水平直线切边 | 牌绕底边铰链翻起（WO1 §2.3），底边直才能贴地；`key_alpha.py` 会量底边接触宽度（§2.5） |
| 上半部轮廓鲜明，缩到 64 像素高仍能认出 | 中等缩放下立牌只有 60–120 像素高，靠剪影识别 |
| 不画地面、草皮、土坡、底座、圆盘；不画任何落影、也不要物体下方的暗色晕 | 影子由实时阴影生成；图里的地面与落影立起来后会变成一块竖着的「影子板」。这是最常见的废图原因，`key_alpha.py` 专门检测半透明暗色 |
| 剪影外缘不要额外描白边或黑边 | 白边由 `PaperMaterial` 按 alpha 生成，图里再描一圈会变成双边 |
| 透明底；做不到就纯品红 #FF00FF 平涂，主体里不用品红 / 洋红 / 亮紫；不要用灰白棋盘格表示透明 | 品红是自然物里最少见的颜色，抠像最稳；棋盘格是模型「假装透明」的常见失败，工具会直接拒收 |
| 正方形 1024×1024；内容里写明「宽约为高的 n 倍」 | 统一画幅便于批处理；宽高比写进 prompt，出图后与清单比对（偏差 > 30% 警告） |

地点立牌另加：「整体分前、中、后三层纸，层间能看到厚度与接触阴影」，以及每类一句辨识要点（城：灰砖城墙或城门、青灰瓦；门派：山门或层层升高的殿阁、少量朱红；镇：无城墙的木构；寨：原木或粗石、粗犷；村：茅草或土墙、矮小）——保证「城 / 镇 / 寨 / 村」在 64 像素下靠材质与轮廓就能分开。

### 2.3 底纸的公共约束

| 约束 | 为什么 |
| --- | --- |
| 正上方垂直俯视、正射，无透视、无地平线、无天空 | 底纸平铺在地面，任何透视都会在相邻格之间对不上 |
| 整幅是平面印刷纸面，什么都不立起来，没有阴影（`GROUND_STYLE`，§2.1） | 试点里的教训：站立的草簇、带暗沿的叠片在平铺后都成了噪声 |
| 有立牌表现的东西底纸里不画：林地、密林不画树冠和树干，园林不画灌木，花谷不画花树（v1.3） | 试点林地底纸画满圆树冠，近档重复感明显，又和林地树牌叠在一起显密；底纸只画林下 / 地面，树交给立牌 |
| 铺满画面，四边无缝、可无限平铺 | 每格从底纸里取一个窗口（§3.2），同种地形相邻时纹理要能接上；`check_tile.py` 量接缝 |
| 没有突出的单个物体或视觉中心；元素大小相近、均匀散布，单个元素约占画面宽度的 1/12–1/6；整张对应 2×2 格 | 有视觉中心的图一平铺就是「同一棵树每隔两格出现一次」；给出元素尺度，避免模型画成一棵巨树或一片细沙 |
| 纹理不能有明显方向（农田、桑园除外：行列与画面上下边平行、横贯整幅，左右能接上） | 运行时随机旋转 90° 并镜像来打散重复；农田、桑园标 `noRotate`，只翻转不旋转 |
| 没有投影、暗角、从一边到另一边的明暗渐变 | 同上，渐变在旋转后会形成棋盘状的明暗格；`check_tile.py` 量左右 / 上下两半的明度差与暗角 |
| 整幅只有一种地表：不画岸线、水边、沙滩、田埂、小路、篱笆或任何边界线，不在一角混进别的地表（湖泊底纸写明「整幅开阔水面，看不到岸」） | 交界由着色器生成（§3.3）：弯曲的交界线、撕开的纸边、浅水带都是实时算的，岸边的芦苇石块是填充小件；图里自带的岸线会每两格重复一次，而且和真实的交界对不上 |
| 颜色比真实地表更浅、更灰 | 季节染色是乘在上面的（§3.2.4），底子灰一些才有余地；`check_tile.py` 的彩度阈值 C ≤ 0.10 |
| 缩到 64 像素见方仍能认出是哪种地形 | 拉远后一格只有几十像素，地形靠底纸的颜色与纹理粗细区分 |

底纸描述里刻意避开「一座 / 一棵 / 中央」这类单体措辞（生成器的措辞检查会拦），并把旧版里会产生视觉中心的描述改掉了：丘陵从「一圈圈同心等高线」改为「许多小圆丘」，暗渊从「一圈圈向下的深坑」改为「许多不规则的小裂口」，峡谷从「平行深沟」改为「弯曲交错的深沟」（避免方向性），园林去掉了「小径」。v1.3 又把各地形描述里的「叠纸 / 纸层」统一改成印刷纹样的说法（如丘陵「三四圈由浅到深的印刷等高线」、湖泊「印着一道道舒缓的浅色水纹弧线」），原野的草簇改为「平贴在纸面上的小草纹样」。

### 2.4 长条、遮罩、浓度图、平放件

| 素材 | 约束 | 为什么 |
| --- | --- | --- |
| 道路纸带、边框条（1024×256） | 横贯画面、左右无缝；带宽约占画面高的六成 / 七成；上下之外透明或品红 | 沿路径重复贴（u 沿长度），左右必须接得上；上下留白让 alpha 镂空出带子的毛边，并由运行时白边做出模切感 |

## 3. 渲染接入方案

### 3.1 加载与资源

- 进入 `RegionScene` 的 `preload` 里通过 `AssetCache.acquire` 取：`region/region-terrain`、`region/region-locations`、本省的 `region/province/<group>`（若有）、底纸数组、5 张装饰纹理。离开时 `release`，WO1 的 5 秒延迟释放覆盖「出去又回来」。
- **图片必须用 `ImageBitmapLoader` 读，且 `setOptions({ imageOrientation: 'flipY', premultiplyAlpha: 'none', colorSpaceConversion: 'none' })`。** 浏览器默认按预乘解码，透明像素的 RGB 会被清零，工具链做的边缘颜色外扩就白做了，远处的牌会出现黑边。WO1 §2.6 的图集加载请一并改成这样（列入 §4 的修改建议）。
- 底纸数组（v1.2 跟画质档走）：medium / low 档（开发期缺省）读 `ground.json` 与 `ground-strip.webp`（768 × 768·18 的竖长图，一次请求一次解码），画到 `OffscreenCanvas` 取像素，建 `DataArrayTexture(data, 768, 768, 18)`；high 档读 1024² 的 KTX2 数组（`build_ground_array.py --size 1024` 出逐层文件，发版构建转 KTX2；1024×18 超过 WebP 长图上限，不出长图），没有 KTX2 时回落到 medium；`low` 档可再跳过最高一级 mip。共同设置：`SRGBColorSpace`、`RepeatWrapping`、`LinearMipmapLinearFilter`、`generateMipmaps = true`、`anisotropy = 4`。逐层的上下翻转不用处理——每格本来就随机旋转 / 镜像（`noRotate` 的两层上下翻转后行列仍然水平）。解码放在 worker 里或分帧做，≤ 25ms。
- 装饰纹理：道路、边框条 `RepeatWrapping`（u 方向）+ `ClampToEdge`（v）；迷雾 `RepeatWrapping` 两向；撕纸遮罩 u `Repeat`、v `ClampToEdge`；都开 mipmap。迷雾与遮罩用 `NoColorSpace`（是数据不是颜色）。
- **`art-manifest.json` 的条目扩展为三种**（`build_manifest.py` 已按此输出，需 WO1 的 `atlas.ts` 同步）：

```ts
type ArtEntry =
  | { atlas: string; frame: string }      // 图集帧（WO1 §2.6 原有）
  | { array: string; layer: number }      // 纹理数组的一层（底纸）
  | { texture: string };                  // 单张纹理（道路、迷雾、遮罩、边框）
```

  `AssetCache.resolve(artKey)` 只处理第一种；新增 `resolveTexture(artKey)` 与 `resolveArrayLayer(artKey)` 处理后两种，缺失时同样回退占位并只警告一次。

### 3.2 地形底纸

#### 3.2.1 数据

- `tTerrain`（WO2 §10.1，不改尺寸）：R = 地形编号（`TerrainType` 的下标，0–21）；**G = 逐格随机字节**，按位拆用：bit0 镜像，bit1–2 旋转（0/90/180/270°），bit3–4 取底纸里的哪个窗口，bit5–7 逐格明暗（原 WO2 的 `0.96 + 0.08·t.g` 改用这 3 位）。随机字节由 `hash(regionSeed, cellIndex)` 确定，同一地区每次进入都一样。
- `tPalette`（WO2 §10.1，仍为 32×4）：第 0 行底色、第 1 行高亮色不变；**第 2 行 = 地形参数**：R = 底纸层号（`terrainToLayer`，5 类聚居都是 17），G = 叠放次序（0–255），B = 标志（bit0 `noRotate`），A 备用；**第 3 行 = 当前季节染色**：RGB = 乘色 × 0.5（128 表示不变，可提亮到 2 倍），A = 去饱和量（冬季用）。
- 叠放次序（写进 `terrain-art.json`，可被内容包覆盖）：`abyss` 10、`lake` 20、`marsh` 30、`farmland` / `herbGarden` / `mulberry` 50、`plain` / `waste` / `garden` / `vale` 60、`settlement` 70、`woods` 80、`jungle` 85、`hill` 90、`canyon` / `cave` 100、`stoneForest` 110、`mountain` 120。水最低、山最高；「低洼 → 平地 → 林 → 丘 → 岩 → 山」。

#### 3.2.2 朝向与窗口

每张底纸覆盖 2×2 格（`uGroundSpan = 2`），一格取其中一个 1/2 × 1/2 的窗口，再做 8 种朝向之一：每种地形有 4 窗口 × 8 朝向 = **32 种**格面变化（`noRotate` 的为 4 × 4 = 16 种）。相对于原方案「整张贴一格、只做 8 种朝向」，这样变化多 4 倍，每格的纹素密度为 medium 384、high 512（v1.2，§1.2）。格与格之间本来就有纸缝，窗口和朝向在格边不连续是「一张张单独裁的纸」，不是瑕疵。

**mip 选择必须用连续坐标的导数**：格边处 `uv` 跳变，若直接 `texture()` 会在格边算出巨大的导数、取到最模糊的 mip，出现一圈细线。用 `textureGrad`，导数取 `vGridUv` 的屏幕导数经同一朝向矩阵变换。

#### 3.2.3 着色器片段

接在 WO2 §10.1 的 `extend` 片段里（替换其中 `base` 的取法与纸缝计算），声明部分插在 `#include <common>` 之后；WO2 片段里已声明的 `tTerrain`、`tPalette`、`uSeamColor`、`vGridUv` 合并为一处，不要重复声明：

```glsl
uniform highp sampler2D tTerrain;
uniform sampler2D tPalette;
uniform mediump sampler2DArray tGround;
uniform sampler2D tEdge;
uniform float uGridN;          // 格数 N
uniform float uGroundSpan;     // 一张底纸覆盖的格数，默认 2
uniform float uTearScale;      // 撕边沿边方向的重复率，默认 2.5（遮罩 4:1、横向 0.4 格一个周期）
uniform vec2 uSeam;            // x = 同种地形的折痕宽 0.008；y = 异种交界的撕边位置 0.035（v1.1「整页纸」）
uniform vec3 uShade;           // x = 接触阴影宽 0.06，y = 强度 0.25，z = 背光侧系数 0.4
uniform vec2 uSeamDark;        // x = 折痕压暗 0.10，y = 撕口压暗 0.15（v1.1：缝里不再是深色底，而是压暗的本色）
uniform vec4 uWarpPhase;       // v1.1 交界扭曲的四个相位，hash(regionSeed) 取 [0, 2π)
uniform vec3 uShallow;         // v1.1 浅水带：x = 宽 0.10，y = 提亮量 0.30；颜色用 uShallowColor
uniform vec3 uShallowColor;    // 默认 (0.86, 0.90, 0.86)
varying vec2 vGridUv;

int gTerrain( ivec2 c ) {
	c = clamp( c, ivec2( 0 ), ivec2( int( uGridN ) - 1 ) );
	return int( texelFetch( tTerrain, c, 0 ).r * 255.0 + 0.5 );
}
vec4 gParam( int t ) { return texelFetch( tPalette, ivec2( t, 2 ), 0 ); }

// v1.1「有机交界」：查格前把坐标扭一下（两组正弦，最大位移 0.16 格，雅可比远小于 1、不会折叠），
// 异种地形的交界就成了弯曲的岸线 / 林缘；与 preview_grid.py 的 warp() 同一公式
vec2 gWarp( vec2 g ) {
	return 0.16 * vec2(
		0.7 * sin( 2.6 * g.y + 0.8 * g.x + uWarpPhase.x ) + 0.3 * sin( 5.3 * g.y - 1.9 * g.x + uWarpPhase.y ),
		0.7 * sin( 2.6 * g.x - 0.8 * g.y + uWarpPhase.z ) + 0.3 * sin( 5.3 * g.x + 1.9 * g.y + uWarpPhase.w ) );
}
bool gWater( int t ) { return ( int( gParam( t ).b * 255.0 + 0.5 ) & 2 ) != 0; }     // 标志 bit1 = 水面

// 朝向码 → 2×2 矩阵：bit0 镜像，bit1–2 旋转；noRotate 时只取 0° / 180°
mat2 gOrient( int code, bool noRotate ) {
	int r = ( code >> 1 ) & 3;
	if ( noRotate ) r &= 2;
	mat2 m = r == 0 ? mat2( 1.0, 0.0, 0.0, 1.0 ) : r == 1 ? mat2( 0.0, 1.0, -1.0, 0.0 )
	       : r == 2 ? mat2( -1.0, 0.0, 0.0, -1.0 ) : mat2( 0.0, -1.0, 1.0, 0.0 );
	if ( ( code & 1 ) != 0 ) m = m * mat2( -1.0, 0.0, 0.0, 1.0 );
	return m;
}
```

主体插在 `#include <alphatest_fragment>` 之前：

```glsl
vec2 g = vGridUv;
ivec2 home = ivec2( floor( g ) );                 // 逻辑格（寻路、选中、悬停都按它）
int homeId = gTerrain( home );

// ── 交界扭曲：扭曲后的坐标决定这一点画成哪种地形；扭到地图外则按逻辑格 ──
vec2 gw = g + gWarp( g );
ivec2 cell = ivec2( floor( gw ) );
if ( any( lessThan( cell, ivec2( 0 ) ) ) || any( greaterThanEqual( cell, ivec2( int( uGridN ) ) ) ) ) { cell = home; gw = g; }
vec2 f = fract( gw );
int id = gTerrain( cell );
// 底纸取哪一格的窗口与朝向：与逻辑格同种 → 逻辑格（同种之间仍是直的折痕）；异种 → 扭进来的那一格
ivec2 own = id == homeId ? home : cell;
vec4 t = texelFetch( tTerrain, own, 0 );
int rnd = int( t.g * 255.0 + 0.5 );
vec4 prm = gParam( id );
float stack = prm.g;
bool noRot = ( int( prm.b * 255.0 + 0.5 ) & 1 ) != 0;

// ── 底纸：窗口 + 朝向，按「原坐标 − 所属格」取（可略出 [0,1]，底纸可平铺、REPEAT 包裹，出界处与格内连续、不变形）──
#ifdef GROUND_ARRAY
mat2 R = gOrient( rnd, noRot );
vec2 f0 = g - vec2( own );
vec2 win = mod( vec2( float( ( rnd >> 3 ) & 1 ), float( ( rnd >> 4 ) & 1 ) ), uGroundSpan );
vec2 uv = ( R * ( f0 - 0.5 ) + 0.5 + win ) / uGroundSpan;
vec2 gx = R * dFdx( g ) / uGroundSpan, gy = R * dFdy( g ) / uGroundSpan;
vec3 base = textureGrad( tGround, vec3( uv, floor( prm.r * 255.0 + 0.5 ) ), gx, gy ).rgb;
vec4 tint = texelFetch( tPalette, ivec2( id, 3 ), 0 );
base = mix( base, vec3( dot( base, vec3( 0.2126, 0.7152, 0.0722 ) ) ), tint.a ) * tint.rgb * 2.0;
#else
vec3 base = texelFetch( tPalette, ivec2( id, 0 ), 0 ).rgb;    // 无底纸：WO2 的纯色格（交界照样弯曲）
#endif
base *= 0.96 + 0.08 * float( rnd >> 5 ) / 7.0;

// ── 四邻：撕边、接触阴影、浅水带在扭曲坐标里算（交界是弯的）；同种地形的折痕在原坐标里算（格线是直的）──
const ivec2 NB[4] = ivec2[4]( ivec2( -1, 0 ), ivec2( 1, 0 ), ivec2( 0, -1 ), ivec2( 0, 1 ) );
float dist[4] = float[4]( f.x, 1.0 - f.x, f.y, 1.0 - f.y );
float along[4] = float[4]( gw.y, gw.y, gw.x, gw.x );
vec2 fh = fract( g );
float distH[4] = float[4]( fh.x, 1.0 - fh.x, fh.y, 1.0 - fh.y );
float seamPx = max( uSeam.x, fwidth( g.x ) * 1.2 );            // WO2：远处缝宽不小于约 1px，防闪烁
float paper = 1.0, crease = 1.0, lip = 0.0, shade = 0.0, shallow = 0.0;
bool water = gWater( id );
for ( int k = 0; k < 4; k++ ) {
	int nid = gTerrain( cell + NB[ k ] );
	float d = dist[ k ];
	if ( nid != id ) {
		// 撕边：沿边坐标查遮罩；相位按边序号与本格地形错开，两张纸的撕口不对称
		float phase = float( k ) * 0.37 + float( id ) * 0.13;
		float m = texture( tEdge, vec2( along[ k ] * uTearScale + phase, d / ( 2.0 * uSeam.y ) ) ).r;
		paper = min( paper, smoothstep( 0.42, 0.58, m ) );
		lip = max( lip, 1.0 - smoothstep( 0.58, 0.80, m ) );      // 撕口露出的纸芯白
		if ( gParam( nid ).g > stack ) {
			// 光从左上：左邻（k=0）与远侧邻（k=3，+y 指向远离镜头）投下的影子更实
			float dir = ( k == 0 || k == 3 ) ? 1.0 : uShade.z;
			shade = max( shade, ( 1.0 - smoothstep( 0.0, uShade.x, d - uSeam.y ) ) * dir );
		}
		if ( water && !gWater( nid ) ) shallow = max( shallow, 1.0 - smoothstep( uSeam.y, uSeam.y + uShallow.x, d ) );
	}
	// 折痕：逻辑格这一侧的邻格与本格同种，且这一点确实画成本格的地形
	if ( id == homeId && gTerrain( home + NB[ k ] ) == homeId )
		crease = min( crease, smoothstep( 0.0, seamPx, distH[ k ] ) );
}
vec3 col = mix( base, uShallowColor, shallow * uShallow.y );   // 水面沿岸一道浅水
col = mix( col, uPaperRimColor, lip * 0.55 );
col *= 1.0 - shade * uShade.y;
col *= ( 1.0 - ( 1.0 - paper ) * uSeamDark.y ) * ( 1.0 - ( 1.0 - crease ) * uSeamDark.x );
// 之后接 WO2 的「未探索压暗」与 §10.2 的高亮，最后 diffuseColor.rgb *= col;
```

实现注意：

- `GROUND_ARRAY` 由 `GridGround` 在底纸加载完成后加进 `defines` 并 `needsUpdate`；`customProgramCacheKey` 要带上它。没有底纸时整段退回 WO2 的纯色格，**零素材可运行**是验收项。
- 撕边遮罩的 v：图片上白下黑，经 `flipY` 后 v = 1 为白（纸）、v = 0 为黑（缝），所以格边（d = 0）是缝、d = 2·`uSeam.y` 处是纸，分界大致在 d ≈ 0.035，起伏 ±0.015。
- 地图外沿（`gTerrain` 被 clamp 到自身）按同种地形处理，只有细缝。地图边框用 `region.frame.*` 另做（§3.8 的预算已含），不在这个着色器里。
- 每像素最多 1 次数组采样 + 10 次 `texelFetch`（扭曲格、逻辑格、各自四邻）+ 至多 4 次遮罩采样（只在异种边）+ 若干调色板读 + 4 次 `sin`，集显上全屏地面 ≤ 1.5ms（§3.9）。
- `tGround` 的 `wrapS / wrapT = RepeatWrapping`：异种交界处底纸按「原坐标 − 所属格」取，会略出本格窗口 0.16 格，靠平铺续接。
- 扭曲只改**画法**，不改逻辑：寻路、移动耗、选中与悬停仍按逻辑格（`CellHighlighter` 勾的还是方格）；一格的立牌、填充小件也只落在「画成本格地形」的地面上（§3.6）。最大位移 0.16 < 主体槽位到格边的最小距离加抖动后的余量，棋子站在格心不会站进水里。
- 纸纤维细节层（v1.2）：地面材质的 `uPaperFibre`（WO1 世界空间纸纤维的强度）由 `RegionScene` 按 `FollowRig` 的当前距离插值——远档 0.22、中档约 0.28、近档约 0.35，随缩放过渡连续变化；立牌不变。不加锐化滤镜。
- `tPalette` 第 2 行 B 通道的标志加 bit1 = 水面（`terrain-art.json` 的 `water`，起步只有 `lake`，取自清单底纸项的 `water` 字段）。

#### 3.2.4 季节染色

`terrain-art.json` 给每种地形四季的染色（RGB 乘色 + 去饱和量）；`GridGround.setSeason(s)`（`s ∈ [0, 4)` 连续，0 春 1 夏 2 秋 3 冬）在相邻两季之间插值后写第 3 行，只在季节进度变化时上传（每游戏日一次足够）。植被类地形立牌（§1.3 的「季节染色」列）同时用 `PaperBatch.setTint` 染同一套颜色。默认值给出四套中性的起步色（夏 = 不变），由美术在画廊页调。

#### 3.2.5 雪景（预留）

不为 18 种地形各出雪景。建议做法：将来加一张可平铺的「积雪」底纸作为第 19 层，冬季按逐格随机数与地形的「积雪系数」在着色器里用撕纸遮罩的形状把它叠在底纸上（水面、暗渊系数为 0）。这样只多一张图。本工单只预留 `terrain-art.json` 的 `snowCover` 字段与数组的第 19 层位置，不实现。

### 3.3 地形边界

做法已在 §3.2.3 的片段里。**v1.1「有机交界」**：用户看了参考后指出，地形之间（尤其水和陆地）的分割应当自然——岸线、林缘不该沿着方格走。着色器先把坐标扭一下（`gWarp`，最大 0.16 格）再查「这一点画成哪种地形」，于是异种交界成了弯曲的线，拐角处的三四种地形也自然地咬合在一起；底纸仍按原坐标取，纹理不变形；水面一侧沿岸再提亮一道约 0.10 格的浅水带，岸边的芦苇、石块由 §3.6 的岸边件补上。这些都不需要额外出图，也**不为任何两两组合出图**；对出图的唯一要求是底纸里不画边界（§2.3）。

其余规则不变：着色器 `texelFetch` 取四邻的地形编号；同种地形之间只有一道 0.008 宽的浅折痕（v1.1：地面读作一整页纸，格线不抢戏，选中、悬停时由 `CellHighlighter` 勾出格子），与本格不同处是位置约 0.035 的撕边（沿弯曲的交界线），撕口里是压暗的本色而不是深色底；按叠放次序，**高的一侧在低的一侧上压一条约 0.06 格宽的接触阴影**。不为任何两两组合出图。

对原方案的两处补充：

1. **撕口露纸芯白**：遮罩分界附近（`m` 在 0.58–0.80）向 `uPaperRimColor` 提亮，与立牌的模切白边是同一种纸芯色——这是「撕开的纸」最有说服力的细节，成本为零。
2. **接触阴影带方向**：光从左上来，所以只有左邻、远侧邻比本格高时阴影是满强度，右邻、近侧邻高时乘 0.4（只剩环境遮蔽的感觉）。若不区分方向，四周一圈等强的阴影会读成「凹坑」而不是「压在上面」。

可选升级（默认不做，画廊页对比后再定；v1.1 的弯曲交界已让高的一侧「伸进」低的一侧，需求小了很多）：**叠压模式**——低的一侧在撕边以内改为采样高侧邻格的底纸，让高的那张纸真的「盖过」格线一点，而不是两边各留一道缝。多一次数组采样，只在异种边的窄带里发生。

### 3.4 未探索迷雾（`FogLayer.ts`）

```ts
export class FogLayer {
  constructor(size: number, cellSize: number, fogTex: Texture);
  readonly mesh: Mesh;                          // 一块 N×N 的平面，y = 0.5
  setExplored(index: number, v: number): void;  // 0 = 有雾，1 = 已探索；写 tExplored
  reveal(cells: number[], durMs?: number): void;  // 揭开动画：这些格的值 0 → 1，默认 600ms，ease-out
  setPalette(paper: Color, ink: Color): void;   // 随灯光预设（warmDay / coolNight）切换
  update(dt: number): void;                     // 推进 uTime 与揭开动画；有改动才上传 tExplored
}
```

- **遮罩**：`tExplored` 为 N×N 的 `R8`，`LinearFilter` + `ClampToEdge`。纹素中心在格心，线性插值让雾的边界在相邻两格之间软过渡。值来自 `core` 的 `TileState.explored`（视野规则见 PLAN §3.6：地图边缘、聚居点及四邻等初始可见）。
- **视差修正**：雾面离地 0.5，俯角 53° 下，从雾面上一点沿视线到地面要向远处偏 0.5 / tan 53° ≈ **0.377 格**。直接用雾面坐标查遮罩，雾洞会比已探索的格子整体往近处错开三分之一格。查遮罩时先把坐标沿视线投到地面：`uParallax = (0, 0.377)`，由相机朝向与 `uFogHeight` 算出（不写死，换俯角也对）。
- **两层平移**：同一张浓度图取两个尺度（0.25 与 0.4 次 / 格）、两个方向和速度（约 0.01 与 0.008 格 / 秒）相加。
- **墨边**：浓度在 0.2–0.6 的过渡带向墨色偏，像墨在宣纸上晕开——这是本场景水墨成分最集中的地方，按「20% 水墨」它应该是最显眼的一处，但只在未探索区域出现。
- **不投影、不受光**：`MeshBasicMaterial` + `onBeforeCompile`（或 `ShaderMaterial`），`transparent: true`、`depthWrite: false`、`castShadow = receiveShadow = false`，`renderOrder` 置于所有不透明物之后。全场只有这一个半透明物体，不需要排序。

```glsl
uniform sampler2D tExplored, tFog;
uniform float uTime, uGridN;
uniform vec2 uParallax;
uniform vec3 uFogPaper, uFogInk;
varying vec2 vGridUv;                                    // 雾面上的格坐标
void main() {
	float explored = texture( tExplored, ( vGridUv + uParallax ) / uGridN ).r;
	float d1 = texture( tFog, vGridUv * 0.25 + uTime * vec2( 0.010, 0.004 ) ).r;
	float d2 = texture( tFog, vGridUv * 0.40 + vec2( 0.5 ) - uTime * vec2( 0.006, 0.009 ) ).r;
	float dens = clamp( d1 * 0.65 + d2 * 0.55, 0.0, 1.0 );
	// 揭开：阈值随 explored 从 -0.05 升到 1.05，云的薄处先散、厚处后散；加 4×4 抖动打散色带
	float edge = mix( -0.05, 1.05, explored );
	float v = dens * 0.8 + 0.1 + ( paperDither( gl_FragCoord.xy ) - 0.5 ) * 0.06;
	float keep = smoothstep( edge - 0.06, edge + 0.06, v );
	float ink = smoothstep( 0.2, 0.35, dens ) * ( 1.0 - smoothstep( 0.35, 0.6, dens ) );
	gl_FragColor = vec4( mix( uFogPaper, uFogInk, ink * 0.5 ), keep * mix( 0.78, 0.96, dens ) );
}
```

（`paperDither` 取 WO1 §2.1 里的同名函数，复制一份即可。）

对原方案的修改：原方案用纯抖动溶解；这里改为**以云的浓度作溶解阈值**、抖动只作打散——视觉上是「云从薄处散开」，比均匀的噪点消失更像纸云。

**探索演出**（`RegionScene.onTilesExplored({ cells, origin })`）：

1. t = 0：`fog.reveal(cells, 600)`。
2. 这些格及其 8 邻里仍为 `FLAT` 的立牌，`batch.rise(h, 0.25 + dist × 0.035)`，`dist` 为到 `origin`（玩家所在格）的欧氏距离（格）。0.25s 的起始延迟让雾先散开一半。地点立牌组里前景件先起（+0），主牌后起（+0.08），形成立体书由前到后的翻页。
3. 新揭开的聚居点在其主牌 `LOCKED` 后 120ms 登记地名标注（淡入）。
4. 首次进入地区：所有已探索格的立牌从玩家所在格开始波纹起立（`delay = dist × 0.02`，上限 0.8s）；从别的场景返回时直接 `LOCKED`，不播。
5. `prefers-reduced-motion`：雾直接消失，立牌直接 `LOCKED`。

**视野外变灰（v1.1，用户 2026-11-23）**：格子有三种状态——未探索（纸云盖住，立牌平躺）、**已探索但不在视野内（灰）**、在视野内（原色）。近档只看棋子周围 3×3，九格之外「一般都是灰的」。做法：

- `tExplored` 从 `R8` 改为 `RG8`：R = 已探索（同上），G = 在视野内（`core` 给出视野半径，缺省 1 = 3×3；随棋子移动更新，同样线性插值、300ms 过渡）。
- 地面：§3.2.3 片段末尾 `col = mix( vec3( dot( col, LUMA ) * 0.8 + 0.1 ), col, 0.15 + 0.85 * vis )`（视野外去饱和 85%、略提亮压平）。
- 立牌：`PaperMaterial` 的 `extend` 里按世界坐标 xz 换算格坐标，查同一张 `tExplored` 的 G，做同样的去饱和——全部立牌、填充小件、地面散件共用一张纹理，不需要逐实例属性。棋子与 NPC 不受影响。
- 远档（缩略图）里视野外同样是灰的，于是一眼能看出「我在哪、看得见哪」。
- `preview_grid.py --sight 1` 按同一规则出图（§7）。

未探索格上的立牌始终 `FLAT`（WO1 `HingeState.FLAT`）。平躺的牌仍在 `BatchedMesh` 里参与阴影通道，但它贴地，影子落在自己身上不可见；需在画廊页确认没有阴影痤疮，有的话把平躺牌的 y 抬 0.003。

### 3.5 道路（`roads.ts`、`RoadLayer.ts`）

**数据**：优先读 `RegionDef.roads?: number[][]`（每条是格下标的折线，内容包手摆）。没有时由 `buildRoads` 生成：

```ts
export function buildRoads(
  size: number,
  cost: (index: number) => number | null,   // 地形移动耗；null = 不可通行
  nodes: number[],                          // 聚居点格 + 驿站格
  opts?: { waterPenalty?: number; isWater?: (i: number) => boolean },
): number[][];                              // 折线（格下标），已合并共用段
```

1. 道路格耗 = 移动耗，水面与暗渊再 × `waterPenalty`（默认 3）——路宁可绕岸走。
2. 节点两两之间用 WO2 §10.4 的 `findPath` 求路径与总耗，在这张完全图上求最小生成树（Prim，节点 ≤ 6）。
3. 生成树每条边取其路径的格序列；把所有用到的「格–格」相邻边去重，拼成图，再在度 ≠ 2 的节点处切开，得到不重复的折线。

**几何**：折线经过格心 → 向心 Catmull-Rom（α = 0.5）平滑，按 0.08 格等弧长采样 → 每个采样点沿水平法线左右各 0.07，挤成宽 **0.14** 的带（v1.1：用户要求道路小一点；近档约 90px，是一条小路而不是大道），离地 **0.004**（多条路交汇处每条再 +0.0005，并开 `polygonOffset`，防 z 冲突）。u = 弧长 / (0.14 × 4)（贴图 4:1，宽 0.14 时 0.56 格一个周期），v = 0 / 1。

**材质**：`createPaperMaterial({ map: roadTex, cutout: true, doubleSided: false })`——镂空得到毛边，WO1 的模切白边自动出现在路沿上。`receiveShadow = true`，`castShadow = false`。全部道路一个 `Mesh`、一次绘制。

### 3.6 一格的布置：主体、填充、地面散件（`dressing.ts`、`RegionDressing.ts`）

纯函数先算出布置，再灌进 `PaperBatch`：

```ts
export interface Placement {
  cell: number; artKey: string;
  x: number; z: number;           // 世界坐标（铰链锚点）
  scale: number;                  // 0.9–1.1
  tint: number;                   // 逐张明度微差 ±4%
  seasonal: boolean;
}
export function placeTerrainStandees(
  size: number, tiles: { terrain: TerrainType; settlement?: SettlementKind; poi?: boolean }[],
  art: TerrainArt, seed: number,
): Placement[];
```

- **主体几张**：`terrain-art.json` 的 `density: [min, max]`，按格哈希取，上限 7（§1.4）。起步值与 §1.3 同源（生成器的 `CELL_DENSITY` 表，写进清单底纸项的 `density` 字段）：`lake` [0, 1]；`farmland` [0, 1]；`plain` [0, 2]；`waste` [1, 2]；`cave` [1, 2]；`canyon` [1, 2]；`abyss` [1, 2]；`herbGarden` [1, 2]；`hill` [1, 3]；`marsh` [1, 3]；`mountain` [1, 2]（v1.3.1，原 [2, 3]）；`garden` [2, 4]；`vale` [2, 4]；`stoneForest` [2, 4]；`mulberry` [3, 4]；`woods` [4, 6]；`jungle` [5, 7]。
- **主体槽位**（格内坐标，x 向右、z 向镜头为正，按从后到前排）：1 张 `(0, -0.05)`；2 张 `(-0.2, -0.15)`、`(0.2, 0.2)`；3 张 `(-0.24, -0.24)`、`(0.22, -0.2)`、`(0.02, 0.22)`；4 张 `(-0.26, -0.26)`、`(0.22, -0.24)`、`(-0.22, 0.2)`、`(0.26, 0.24)`；5 张再加中间 `(-0.02, -0.02)`；6 张后排 `(-0.3, -0.3)`、`(0.02, -0.26)`、`(0.3, -0.28)`，前排 `(-0.28, 0.18)`、`(0.04, 0.24)`、`(0.3, 0.16)`；7 张后排 3、中间 `(-0.14, -0.02)`、`(0.18, 0)`、前排 `(-0.3, 0.26)`、`(0.28, 0.26)`。各加 ±0.06 的哈希抖动、0.92–1.08 的缩放，再乘 §1.4 的张数缩放。高的牌占后排槽。若牌脚所在的点按 §3.2.3 的扭曲画成了别的地形（交界弯进了本格），把偏移乘 0.6 向格心收，至多 3 次。
- **填充小件**：张数与候选池取自清单底纸项的 `fillers`（§1.5）。位置在格内 `[-0.43, 0.43]²` 里按哈希撒点，与本格已有的立牌底边中心至少相距 0.13，且这一点画成本格的地形（拒绝采样，至多 24 次）；**水面格**的填充小件只接受离岸 0.12 格以内的点（芦苇、石块长在岸边浅水里，湖心是开阔水面）；缩放 0.85–1.15；`order` 最低（同 z 时先画）。季节染色同植被立牌；另按地形乘 `terrain-art.json` 的 `fillerTint`（例如荒野偏黄灰、暗渊压暗），同一张灌木在林地与花谷里颜色不同。
- **岸边件**（v1.1）：与水面相邻的陆地格（聚居格除外）再沿岸撒 1–3 张 `reeds` / `rock.0` / `tuft.1`——点要画成本格地形、且 0.12 格内有水面，彼此相距 ≥ 0.11（至多 40 次）。数据取自湖泊底纸项的 `shore` 字段（生成器的 `SHORE` 表），水面地形取自 `water` 字段（`WATER_TERRAINS`）。判定「这一点画成哪种地形」用与着色器同一个 `gWarp`，`dressing.ts` 导出 `ownerAt(x, z)` 供两处共用。
- **地面散件**：张数与候选池同上（水面不放）；中心在格内、离格边至少 0.35 × 边长，边长 ×0.8–1.2，随机转角。实现为平放的牌（WO1 `HingeState` 固定 `FLAT`，y = 0.002，`castShadow = false`），与填充小件同在 `region/region-detail` 图集、同一个 `PaperBatch`；它们会被格子的季节染色一起染。
- `preview_grid.py` 用的是同一套规则（槽位、缩放、撒点间距），预览图可直接当这几条的目视样张。
- **选帧**：A / B 按哈希取；一格两张以上时不重复同一帧（只有一帧可用时除外）。
- **不镜像**：图里的光从左上来，镜像会让光变成右上，与实时阴影矛盾。变化靠 A/B、缩放、明度微差、槽位抖动。
- **朝向**：主体与地点 `yaw = 0`，正对镜头（镜头朝向固定）；填充小件 `yaw` 在 ±12° 内按哈希抖动——papertrails 的小卡都带 ±14° 的转角，立体书的「纸是立起来的」感觉很大一部分来自这点侧光与厚度。图里的光仍按左上画，±12° 不会穿帮。
- **聚居点邻格让位**：城、门派驻地的 8 邻，镇、寨、村的 4 邻，去掉朝向聚居点一侧的主体槽位（与指向聚居点的方向点积 > 0.05 的槽），且张数比本应的少 1（至少留 1 张，放在远离聚居点一侧）；填充小件不受限。野外地点格（驿站、废墟、奇遇标记）与聚居格不放地形立牌与填充小件，只放地面散件。
- **拾取**：地形立牌（高都 ≥ 0.45）全部用 `GridPicker.registerTall` 登记（包围盒取 `x ± w/2`、`y ∈ [0, h]`、`z ± 0.05`），点到树冠上选中的是树所在的格而不是它身后的格。
- **合批**：地形立牌与前景件同在 `region/region-terrain` 图集、一个 `PaperBatch`，容量 `cards = 7 × N² + 64`、`frames = 40`（图集余量约到 46，见 §1.2）；填充小件与地面散件在 `region/region-detail`、另一个 `PaperBatch`，容量 `cards = 11 × N²`（15×15 时 2475 张）、`frames = 27`。
- **远档细节层**：远档（缩略图）下填充小件与地面散件整体 `FLAT` 并隐藏（随缩放过渡 300ms 折倒），只留主体、地点与道路，缩略图不糊成一片；近、中档全显示。

### 3.10 退化

- **零素材**：无底纸 → 纯色格（`GROUND_ARRAY` 不定义）；无图集 → WO1 占位牌；无迷雾图 → 迷雾用 WO1 的纤维纹理 B 通道（大尺度斑）代替浓度；无遮罩 → 撕边退化为直边（`m = smoothstep(0, 2·uSeam.y, d)`）；无道路图 → 道路用纯色卡纸。全部不报错，只按 WO1 的规则每个 key 警告一次。
- **`low` 画质**：关闭接触阴影与撕边（`uShade.y = 0`，异种边按同种处理但折痕宽改为 0.035）；填充小件每格至多 2 张、地面散件至多 1 张，迷雾只取一层；**不建地形纸层、不摆单栋房屋**（回到 v1.2：平地面、整张聚落立牌，§3.12.4、§3.13.7）。
- **v1.3 两项的开关**：`terrain-art.json` 的 `layers: false` 关纸层，`houses: false` 关房屋（回到整张聚落立牌），互相独立；房屋图集 `region/region-houses` 缺失时自动回退整张聚落立牌，纸层没有素材依赖。

### 3.11 阴影相机跟随可视范围（`shadowFit.ts`）

方向光的正交阴影相机**只覆盖镜头看得见的范围外扩 2 格**，跟着镜头走，并按阴影贴图的纹素对齐，防止移动时影子边缘闪烁。按整张地区图收紧（WO2 §10.5 原文）在 30×30 时只有约 50 texel / 格（`warmDay` 光向下 30×30 在光空间约 41×34），撑不起 128px 以上的格子；跟随可视范围后：

| `FollowRig` 档位（1080p 横向格数） | 地面可见范围（远边宽 × 纵深） | 光空间外扩后 | 2048² 下每格 texel | 屏幕每格 px |
| --- | --- | --- | --- | --- |
| 近 3 格（3×3 视野） | 3.7 × 2.2 | 9.0 × 8.2 | 约 229 | 640 |
| 中 6 格 | 7.3 × 4.4 | 12.4 × 11.3 | 约 165 | 320 |
| 远（整张 15×15 缩略图） | 整张地区 | 20.6 × 17.6 | 约 100 | 约 85 |

远档本来就看整张图，等于按包围盒收紧；近、中两档跟随。（对照：30×30 整图约 50 texel / 格。）阴影本来就是 PCSS 软影（WO1 §2.5），texel 为屏幕像素的三分之一到一半已足够（近档 229 / 640）；`ultra` 档可把阴影贴图升到 4096²。

做法：

1. **范围**：每个缩放档算一次——把屏幕四角的射线与 `y = 0`、`y = 1.2`（最高立牌：门派驻地）两个平面求交，取全部交点，xz 方向各外扩 2 格（覆盖可视范围外、影子落进来的投影体：最高 1.2 的牌在 `warmDay` 下影长约 0.9 格），变到光空间求包围矩形，**取宽高中较大者作正方形边长并固定下来**。档位切换的动画期间用两档中较大的边长，到位后再换，避免 texel 尺寸连续变化。
2. **跟随**：每帧取注视点在光空间的坐标作阴影相机中心。
3. **纹素对齐**：`texel = 边长 / mapSize`；中心的光空间 x、y 各取 `round(v / texel) × texel` 后再变回世界坐标设给 `light.position` 与 `light.target`。镜头平移时影子按整 texel 跳，看不到亚像素抖动。
4. **深度**：near / far 按整张地区图的包围盒（含最高立牌）在光方向上的投影固定，不随镜头变，深度精度一致。
5. **更新**：对齐后的中心与上一帧不同（即跨过了一个 texel）时置 `shadowMap.needsUpdate = true`；与 §3.9 的「静止时不重画」规则合并：`needsUpdate = 中心变了 || 有牌在动 || 棋子在动 || 灯 / 季节变了`。
6. **测试**：`shadow-fit.test.ts`——任意注视点下，可视范围外扩 2 格的地面四角都落在阴影相机的 left / right / top / bottom 内；镜头平移 0.3 texel 时中心不变、平移 1 texel 时中心恰好跳 1 texel；三个档位的边长互不相同且各自恒定。

### 3.12 单栋房屋立牌（`houseRecipes.ts`，v1.3.1）

#### 3.12.1 为什么

整张聚落立牌（C 类 11 张）在近档一格约 640px、俯角 53° 时一眼是平的。v1.3 试过**折纸房屋**：程序搭纸盒，贴 GPT 画的平面部件。预览里纸盒的硬边与平涂的面和手绘插画立牌风格不搭（用户 2026-11-24：现在的屋子和原画风格格格不入），于是改为 GPT 按风格基准 `terrain.standee.woods.0` **一栋一栋画单独的房子，每栋一张立牌**。房子仍然一栋一栋地摆，前后错落、各自投影、互相挡住一部分，比整张聚落立牌立体；画风则和林地、山岳立牌出自同一套 prompt。

纸盒方案（HouseBuilder、19 张部件贴图、`build_house_kit.py`、v1.3 的 §3.12 全文）搁置，代码与工单原文存在仓库的 `docs/shelved/house-boxes/`（`build_house_kit.py`、当时的 `preview_grid.py` / `region_prompts.py` / `test_v13.py`、v1.3 的 §3.12 全文 `wo-v1.3-section-3.12.md`），以后要做「可旋转的房子」时再拿出来。

**坐标约定**：本节与 §3.6、§3.7 相同，以格心为原点，x 向右、z 向镜头为正，范围 ±0.5（`houseRecipes.ts` 的输出直接和 `LocationGroups` 的前景件放在一起）。参考实现 `preview_grid.py` 用的是 [0, 1] 的格内坐标，换算 = 本节的值 + 0.5。

同一 houseKind 有几款时按哈希选款（约束 7 先剔掉本格已用过的款）；每栋另乘 0.92–1.08 的随机系数。约束（全部有测试）：
1. **空地**：格心半径 0.18 内不放房子（棋子站位与地名）；门派驻地的空地是殿阁前的院子，中心 (0, +0.24)、半径 0.14。殿阁靠后居中（x = 0 ± 0.03，z = −0.3…−0.2）。
2. **避路**：道路中线外扩 `ROAD_W/2 + 0.02` 内不放。
3. **四角在本格**：占地矩形 = 立牌宽 × 进深 0.12（`HOUSE_DEPTH`，立牌底边在矩形中线上），四角按扭曲后的 `ownerCellAt` 都要等于本格。
4. **互不相交、后面那栋露得出来**：占地矩形用 SAT 判，留 0.02 间隙；横向重叠超过较窄一栋宽度的三成时，后面那栋在屏幕上至少露出自身高度的一半——俯角 53° 下即 `(z前 − z后) · tan53° ≥ h前 − 0.5 · h后`。
5. **不挡棋子（v1.3.1）**：以空地中心为顶点、朝镜头方向（+z）±40°、半径 0.45 格的扇形内不放房子，只允许前景小件。门派驻地的院子同理（顶点是院子中心）。实现：`preview_grid.in_view_sector`（多边形边上取点落进扇形，或扇形里取点落进多边形）。
6. **先缩再减（v1.3.1）**：放不满下限时，整组依次按 0.9、0.8 倍尺寸重摆（`HOUSE_SHRINK = (1.0, 0.9, 0.8)`），取放得最多的一次；仍不够才少放，**不报错**。预览实测 200 个种子达到下限的比例（含约束 7）：村 99.5%、寨 99.5%、镇 83.5%、城 90.5%、门派 100%。
7. **同一格不重复同一张图（2026-11-24，执行主管；同 §3.6「一格两张以上不重复同一帧」）**：每次尝试（`tries`）先抽种类 k（同前），再在 k 的各款里剔掉本格已用过的 artKey，得到 `fresh`：
   - `fresh` 不空：`pool = fresh`，只试 `pool[h32(seed, i, j, 305, tries) % len(pool)]` 这一款（与原来同一个哈希，只是池子变小）；
   - `fresh` 为空（k 的款都用过了，只能重复）：`pool` = k 的全部款，从 `h32(…305…) % len(pool)` 那款起依次试每一款；都不行，再按配方候选的**去重后顺序**试其他种类里还没用过的第一款（只在这一处原本放不下时才用，放得下时结果不变）。
   - 重复用同一张图时，两栋相同的**不能相邻**：本格已放的各栋加上这一栋，按 (x, z) 升序（屏幕从左到右）排开，这一栋的左右邻居都不能是同一个 artKey。
   - 每个候选都走约束 1–5 的同一套检查（`_house_fits`），第一个通过的放下，本次尝试结束。参考实现：`preview_grid._place_once` / `_house_fits` / `_same_key_adjacent`；测试 `test_v13.HouseTest.test_no_repeat_while_variants_left`、`test_forced_repeat_not_adjacent`（每种只给一款图时 200 个种子无相邻重复）。一格扣掉扭曲内缩（至多 0.16）、空地与扇形后放不下更多；要更密就让镇、城占两格。
- 参考实现：`tools/art/preview_grid.py` 的 `place_houses` / `_place_once` / `_house_fits` / `_same_key_adjacent` / `_blocks` / `house_types_from`，哈希与 `h32` / `hf` 相同；`houseRecipes.ts` 按它移植，测试对同一组种子比对结果（约束 7 加入后，原来 40 个种子的比对基准要重新生成）。

#### 3.12.4 其他

- 出现动画：与立牌相同的起立（`HINGE_RISE`）。**节奏并入 §3.4 的探索波纹**：延迟与同格的立牌用同一个基准和同一套公式——探索时 `0.25 + dist × 0.035`，首次进入地区 `dist × 0.02`（上限 0.8s），`dist` 为房子所在格到探索触发点（玩家所在格）的欧氏距离；同一聚居格里的房子按「前景件 +0、房子 +0.08」排在前景件之后（相当于原来的主牌），格内各栋再按到镜头的远近加 0–0.04 错开。`prefers-reduced-motion` 下直接立好。
- 拾取：每个聚居格登记一个高盒子（各栋包围盒的并）。地名标注挂在格内最高一栋的顶上 0.1。
- 落影：和其他立牌一样由阴影贴图实时投下（预览里同一套立牌投影）。
- **回退（低画质档 / `houses: false` / 房屋图集缺失）**：C 类 11 张整体聚落立牌。
- 房子开着时，聚居格不再画整张聚落立牌，只保留前景件（篱笆、石灯等）。

### 3.13 地形纸层（`TerrainLayers.ts`、`unwarp.ts`，v1.3）

#### 3.13.1 层号

一层厚 `levelStep` 格，**是 `terrain-art.json` 顶层的可调参数**（缺省 0.05；0.05 与 0.08 的对比交用户定，§7.5），代码里不写死；侧壁高度、立牌与房屋的落点、拾取修正、迷雾高度、`maxCasterHeight` 全部按它算。层号写进 `terrain-art.json` 的新字段 `level`（内容包可调），默认：

| 地形 | 边缘层 | 每深入一格 | 封顶 |
| --- | --- | --- | --- |
| mountain 山岳 | +1 | +1 | +3 |
| stoneForest 石林、cave 洞穴 | +1 | 0 | +1 |
| lake 湖泊、canyon 峡谷 | −1 | 0 | −1 |
| marsh 沼泽 | −0.5 | 0 | −0.5 |
| abyss 暗渊 | −1 | −1 | −2 |
| 其余（**含 hill 丘陵**，用户定） | 0 | — | — |

格的层号 = 按「到本地形区域边缘的格距」多源广度优先：有异种四邻的格是边缘（深 0），往里每深一格加一次增量，封顶。地图外按同种处理（不算边缘）。实现：`preview_grid.cell_levels`。

#### 3.13.2 轮廓：unwarp，不做 marching squares

- 交界本来就是扭曲后的格线（§3.2.3 的 `gWarp`），所以纸层轮廓 = **把格线反扭曲**：`x ← u − wx(x, z)` 不动点迭代（偏导上界约 0.55 < 1，收敛）；20 次到 1e-5。测试：1000 个随机点往返误差 < 1e-4。
- 几何在格坐标里建：每格顶面是正方形，每条边切 8 段，相邻格共用顶点，然后**每个顶点 unwarp**。地图外沿不 unwarp（直边）。
- **第一级台阶落在精确交界上**；同种地形内部更高（或更深）的台阶在本格里**内缩 `LEVEL_INSET = 0.07`**（格坐标里把格边平移后再 unwarp）。层号场的定义（`level_field`）：本格层号；离「同种、但层号离 0 更近的邻格」那条格边不足 0.07 时取邻格的层号。
- 侧壁只在两侧层号不同的边上生成：异种交界由高的一侧生成一次；同种内缩台阶由离 0 更远的一侧生成。**地区外沿上层号不为 0 的格都补一道接到书页（0 层）的纸边**：抬起的格从 0 到层高、朝外；下陷的格（湖泊、峡谷、暗渊贴着地图边时）从层高到 0、朝坑内——不补就会在书页与湖面之间露缝（v1.3.1）。下陷的侧壁法线一律朝坑内。

#### 3.13.3 几何与材质

- 一个 `BufferGeometry`、一次 draw call。15×15 约 7k 顶面三角形 + 13k 侧壁三角形。
- 顶面沿用 `GridGround` 的地面材质（同一个着色器，只抬高 y）。
- 侧壁 `aSide = 1`：纸芯白，朝光程度 `0.80 + 0.20·max(0, n·L)`，下半截再压暗一成。侧壁带 `aCell`（高的那一格）用于灰化与迷雾。
- **只有朝镜头的侧壁读得出来**：朝 ±x 的直侧壁在镜头里几乎是侧着看（预览里只有 1–2px），弯曲交界拐向镜头的那几段才看得到。这是对的，不用补。

#### 3.13.4 着色器

- 有高度差的交界不再画撕边和接触阴影（由真实侧壁和影子代替）；同一层里的异种交界照旧画撕边。按边判断：邻格层号与本格相同才画。
- **层号编码（定案）**：`tTerrain` 四个通道都已占用（`GridGround.ts`：R 地面类型、G 图集行、B 高亮位 0–5 只剩 2 位、A 逐格明暗），放不下。新增一张与它同尺寸的 **`tLevel`（N×N，R8，最近邻采样）**，存**格的**层号 `r = (level + 2) × 2`，取值 0–10，覆盖 −2…+3、步长 0.5；读出 `level = r × 255 / 2 − 2`。不用 `uLevel[16]`：山岳的层号随深度变，只按地形 id 查表表达不了。片元里按 §3.2.3 已有的做法取本格与邻格，**两格的 `tLevel` 相同才画撕边与接触阴影**。内缩台阶不进纹理（同种地形之间本来就不画撕边）。
- 浅水带照旧（只看水 / 非水，不看层号）。

#### 3.13.5 地面上的东西

- 立牌、填充小件、地面散件、棋子、房屋：y = 所在点层号 × `levelStep`（按 unwarp 后的 `level_field`）。
- 落点离层边界不足 `LEVEL_EDGE_GAP = 0.04` 的拒绝（四个方向各探 0.04，层号都相同才收），免得纸片骑在崖边上。
- 道路：沿用层高；跨层处加长 0.08 的坡；路径规划尽量避开非 0 层（第二期）。预览里道路仍画在顶面颜色里，跨湖时会「沉」进坑里，这是预览的已知简化。
- 迷雾平面抬到最高层之上；阴影相机 `maxCasterHeight` 加最高层高度（3 × `levelStep`）。

#### 3.13.6 拾取的高度修正（必须做）

y = 0 平面求交会选错抬高的格：0.15 高、53° 俯角时偏差约 0.11 格。做法：先与 y = 0 求交得格，查该点层高 h，再与 y = h 平面求交一次（必要时再迭代一次）。测试：`test_v13.CastTest.test_picking_needs_height_correction`（天真求交偏差 > 0.08，修正后 < 1e-6）。

#### 3.13.7 回退

低画质档或开关关：不抬层、不建侧壁，撕边与接触阴影恢复到所有异种交界（= v1.2）。预览：`preview_grid.py --flat`。

- `tTerrain.g` 的语义从「逐格随机数」细化为按位拆用（§3.2.1），仍由 `GridGround` 内部生成。

- §10.1 的着色片段替换为 §3.2.3（纯色路径保留在 `#else` 分支，WO2 的验收不受影响）。
- §12 的测试表加一条：`ground-shader` 锚点测试——`extend.apply` 后片元源码含 `textureGrad( tGround`、`gOrient(`，且在不定义 `GROUND_ARRAY` 时不引用 `tGround`。

**格子尺寸与地区格数（PLAN §3.6 / M3-WO2 §10；总监 2026-11-23 已确认：`RegionDef.size` = 15 / 10，每格移动消耗不变、世界等比缩小；资源格数与聚居点间距的数值留到 M2 数值平衡工单）**

- 用户 2026-11-23 定：格子放大到原来的 4 倍面积，以求「走进森林」的探险感；最近一档只看棋子周围 3×3，九格之外一般是灰的；拉远就是整张地区的缩略图；同时地区地图缩到原来的 1/4 大小。**渲染侧已按 15 / 10 定（v1.2 执行主管裁定）：省会、门派地区 15×15，乡村地区 10×10**（格子总数为原来的 1/4，整张地区图的屏幕面积与原方案相当）。尺寸保持数据驱动，渲染与美术的任何地方不写死 N。PLAN §3.6 的 `RegionDef.size` 与随之牵动的数值（穿过一个地区的行动力消耗减半、每个地区的资源格数降到四分之一）归总监定。
- `FollowRig`（M3-WO2 §9.2）的三档改为（1080p 横向格数）：近 3（进入地区时的默认档，注视点就是棋子所在格心，**不设死区**——3×3 视野要始终以棋子为中心）、中 6（死区 1 格）、远 = 整张地区装进画面（注视点固定在地区中心，不跟随）。**视场角 27°（v1.2 裁定，不用 35°）**：全套纸片场景（城镇、大地图俯冲对接、PLAN §4.0）都按 27° 定，dive / rise 两端要对得上；近档只有 3 格横宽时，窄视场让前后两行的透视差更小、立牌大小更一致。**相机距离一律由横向格数算出，不写死**：水平视场 = 2·atan(tan(13.5°)·宽高比)，距离 = (横向格数 / 2) / tan(水平视场 / 2)；16:9 下近档 3 格约 3.5、中档 6 格约 7.0、远档（15×15 约 23 格）约 27（格 = 1 单位）。「注视点限制在地图边缘向内 2 格」只对中档生效，改为 1.5 格；近档允许看到地区外的书页空白。俯角维持 53°（用户给的示意约 40°、近大远小更强，若要改俯角，§1.2 的屏幕高度与 §3.11 的数字都要重算，由执行主管定）。
- 视野：`core` 需要给出视野半径（缺省 1，即 3×3）与逐格「在视野内」，供 §3.4 的视野外变灰；若 PLAN 的视野规则与此不同，以 PLAN 为准、只改半径。

**v1.3 对 M3-WO2 的修改（§3.12、§3.13；v1.3.1 补）**

`GridPicker`（M3-WO2 §10.3）——按层高修正拾取（§3.13.6）。**以 M3-WO2 v1.2 §10.3 为准**（已并入），这里只摘要：

```ts
export class GridPicker {
  pick(ndc: Vector2, camera: Camera): number;   // 签名不变：屏幕点 → 格子下标，地图外 −1
  setHeightAt(fn: ((x: number, z: number) => number) | null): void;   // v1.2 新增；世界 xz → 地面高度（层号 × levelStep，地图外 = 0）；null = 平面（low 档）

// pick 内部：与 y = 0 求交 → h = heightAt(x, z) → 与 y = h 再求交，h 变了就再迭代（至多 3 次）；登记的高盒子（registerTall）照旧优先
```

`heightAt` 由 `TerrainLayers` 提供（`layers.heightAt`，同一份层号场：unwarp 后取 `level_field`），不在 `GridPicker` 里复制层号逻辑。

`GridGround`（M3-WO2 §10.1）：

- 新增 `tLevel`（N×N，R8，最近邻）与 `setLevels(levels: Float32Array | null)`：写格的层号（编码见 §3.13.4），并置 `LAYERS` define 让撕边与接触阴影只在同层交界上画；`null` = 全 0 层（WO2 原行为）。
- 顶面由 `TerrainLayers` 的几何承载时，**原来那块平面保留、不画**（`visible = false`）：它仍是 low 档与 `layers: false` 时的地面，切换画质档时只切可见性，不重建；`TerrainLayers` 的顶面直接复用 `GridGround` 的材质实例（同一组 uniform：`tTerrain`、`tLevel`、`tExplored`、季节），所以高亮（`CellHighlighter` 写的 `tTerrain.B`）、视野灰化、季节都自动跟着顶面走，不用另做。
- 选中格、悬停格那张小方纸本来就画在地面着色器里，随顶面抬高，无需改；若 WO2 实现成独立的叠加网格，则它的 y = 该格层高 + 0.002。

`RegionScene`（M3-WO2 §10.5）：

- 新增挂点 `layers: TerrainLayers | null`（开关与回退见 §3.10）；房屋是普通立牌，由 `LocationGroups` 按 `houses` 开关决定用配方还是整张主牌，不另设挂点。`enter` 的顺序变为：建地面 → **算层号、建纸层、`ground.setLevels`、`picker.setHeightAt(layers.heightAt)`** → 算布置（落点 y 取 `layers.heightAt`）→ 建立牌与**房屋** → 道路 → 迷雾 → 标注。
- 棋子与 `TokenMover`：落点 y = `heightAt(格心)`；跨层移动时沿路径按 `heightAt` 插值（经过侧壁处走 0.08 格长的坡，与道路一致），不瞬移。
- 迷雾平面：y = 最高层高 + 原来的离地高度；视差修正（§3.4 `fogParallax`）按新的雾面高度重算。
- 标注（`LabelProjector`）的锚点 y 加所在格层高。

阴影：§3.11 的 `fitShadowCameraToView` 的 `maxCasterHeight` = 1.2（最高立牌）+ 最高层高（3 × `levelStep`）；房屋立牌最高 0.55（殿阁）低于 1.2，不另加。投影体的深度范围同样按此放宽。

## 5. 专属地点槽位

### 5.1 用法

内容包负责人写一份槽位 JSON，运行：

```bash
python3 tools/art/region_prompts.py --slots content/base/art/region/slots.json
```

生成器把每个槽位展开成一条地点立牌 prompt，追加为 `region.md` 的「G. 专属地点」一节，同时把它加进 `region-assets.json`（图集 = `region/province/<group>`，像素密度 400px / 格）。`--check` 会校验字段与措辞。

### 5.2 格式与字段

```json
{
  "slots": [
    {
      "artKey": "loc.city.<slotId>",
      "group": "<该省的 artGroup>",
      "archetype": "建筑原型：从 §5.3 选一项的通用描述，可改写",
      "setting": "坐落环境：地形与周边，如「两条河交汇处的平原」",
      "color": "主色调：一到两种低饱和的颜色",
      "accent": "点缀色：一种颜色，只用在少数构件上",
      "feature": "最醒目的一处构件：让它与其他城区分开的那个东西",
      "note": "（可选）给出图人的备注，不进 prompt"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `artKey` | 是 | `loc.city.<slotId>` 或 `loc.sectSeat.<slotId>`；`slotId` 只含字母、数字、`_`、`-`，不能用 `default.*`。前缀决定类别、尺寸与辨识要点 |
| `group` | 否 | 专属图集的分组，通常 = 该省的 `ProvinceDef.artGroup`；缺省进 `region/province/_ungrouped` |
| `archetype` | 是 | 建筑的整体形制，≤ 60 字 |
| `setting` | 是 | 环境，≤ 60 字；只写地形地貌，不写地名 |
| `color` | 是 | 主色调，≤ 60 字 |
| `accent` | 是 | 点缀色，≤ 60 字 |
| `feature` | 是 | 标志性构件，≤ 60 字；是一个「东西」，不是一句话的气氛 |
| `note` | 否 | 不进 prompt |

所有文字字段**不得出现**：任何地名、门派名、人名、朝代名；「字、匾、招牌、题词、印章、落款」等会诱导出文字的词；「影子、投影、倒影、地面、草地、底座」；「人物、行人」；「品红、洋红」。生成器的措辞检查会拦住其中的固定词，名称类只能靠填写人自觉——这是硬性边界。

### 5.4 颜色约束

- **主色调**：低饱和，按 OKLCh 理解 C ≤ 0.08（文字上用「灰调的 / 暗哑的 / 旧的」来描述）；与通用款共存时不突兀。

- 避开品红、洋红、亮紫（抠像色）；避开接近纯白、纯黑的大面积主色（白边与纸缝会失去对比）。
- 出图后用 `check_tile.py --no-chroma` 看平均色只是参考；点缀色是否协调以目视为准，把该省的专属牌与通用款、该省的大地图强调色放在一张对照图上看。

### 7.5 纸层与房屋的目视判据（渲染会话实现后对照预览）

- 台阶高度在屏幕上（`levelStep` = 0.05）：近档约 19px、中档约 10px、远档 2–3px。
- **层厚 0.05 还是 0.08（v1.3.1，待用户定）**：v1.3 的预览里山岳抬层、湖泊下陷只剩交界上一条细白线，几乎读不出。原因有两个，分开处理：
  1. 山岳的占位底纸原是灰蓝色，和视野外的灰、湖泊的蓝几乎一样。已把占位色调成暖灰褐 `(0.62, 0.56, 0.48)`；批量出图时把 `terrain.ground.mountain` 与 `terrain.ground.lake` 排在底纸的最前面。
  2. 层厚本身。对比图 `art/region/review/compare-level-step.jpg`（近档、中档各一组，左 0.05、右 0.08；单张原图 `cmp-near-ls0.05.png` 等），预览开关 `--level-step`。0.08 时湖岸那道纸崖在近档明显得多，山岳的台阶在中档也能读出；代价是近档台阶约 30px，崖后立牌被挡住的脚更多。
  真实渲染里侧壁有软阴影、顶面有接触阴影，会比预览好读，**最终取值以渲染会话实现后的画面为准**，预览只用来缩小范围；改值只改 `terrain-art.json` 的 `levelStep`。
- 沼泽 −0.5 在中档只有约 5px，读不出就降为 0 层（`terrain-art.json` 改 `level`，不改代码）。
- 四格交汇的角上可能需要 0.04 的倒角；预览里看不出明显尖角，先不做。
- 预览命令：`python3 tools/art/preview_grid.py --zoom near --sight 1 --region 15 --terrains plain,woods,mountain,lake,marsh --houses`；`pilot.sh` 已加一张 `preview-near-s1-houses.png`。
